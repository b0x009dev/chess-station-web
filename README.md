# ChessStation Web

Веб-интерфейс шахматной информационно-аналитической системы ChessStation. Первая версия поддерживает поиск классических партий, редактирование на доске и обмен партиями в формате PGN.

## Демо

Демо-стенд проекта доступен по адресу:

[http://201.34.159.85/chess-station/](http://201.34.159.85/chess-station/)

Ссылка на репозиторий с backend:

[https://github.com/b0x009dev/chess-station-api](https://github.com/b0x009dev/chess-station-api)

На опубликованном стенде доступны страница «Партии» и экран «Новая партия» с начальной расстановкой. Полный интерфейс v1 доступен при локальном запуске обоих репозиториев.

## Назначение проекта

`chess-station-web` – репозиторий веб-интерфейса ChessStation. Его основная задача – дать пользователю возможность найти партию, изучить её ходы, отредактировать продолжение или создать новую запись.

Веб-интерфейс загружает партии с сервера, воспроизводит их на доске и проверяет ходы. Новую или импортированную партию можно редактировать и экспортировать до первого сохранения. Сохранённая партия доступна по прямой ссылке.

## Место веб-интерфейса в общей системе

Проект состоит из двух самостоятельных репозиториев.

- `chess-station-api` – HTTP API, проверка заголовков PGN, поиск и сохранение партий в PostgreSQL.
- `chess-station-web` – список партий и редактор, проверка ходов, импорт и экспорт PGN в браузере.

Такое разделение позволяет независимо развивать, тестировать и разворачивать каждую часть системы. Веб-интерфейс обращается к HTTP API для получения и сохранения партий. Другие клиенты смогут работать по тому же контракту.

## Основные возможности интерфейса первой версии

- Список партий с поиском по имени белых или чёрных и выдачей по 20 партий на странице.
- Открытие сохранённой партии по прямой ссылке.
- Ввод ходов кликом и перетаскиванием, переворот доски и просмотр партии по полуходам.
- Изменение продолжения из промежуточной позиции после подтверждения.
- Редактирование имён игроков, события, даты и результата.
- Создание партии, импорт одного PGN-файла, сохранение, экспорт и удаление сохранённой партии.
- Просмотр и экспорт исходного PGN сохранённой партии, которую редактор не может открыть для правки.

## Обоснование выбранного стека

- HTML, CSS и нативный JavaScript – разметка, оформление и управление интерфейсом через DOM.
- `chess.js` 1.4.0 – представление шахматной позиции, проверка легальности ходов и воспроизведение партий из PGN.
- Vite – локальный сервер разработки, проксирование запросов и статическая сборка.
- ESLint – статическая проверка JavaScript.

## Почему нативный JavaScript и DOM

Веб-интерфейс разрабатывается на нативном JavaScript по условиям задания, чтобы закрепить работу с DOM. Переключение экранов и построение доски выполняются средствами браузера. CSS Grid определяет расположение клеток и панелей. Фигуры отображаются локальными SVG.

Доска получает готовую позицию из `chess.js`. Разметку и оформление клеток можно менять независимо от шахматных правил. Клик и перетаскивание передают редактору исходную клетку и клетку назначения. Редактор проверяет ход по одним правилам для обоих способов ввода.

## Архитектура веб-интерфейса

- `main.js` открывает экран по адресу и обрабатывает переходы с несохранёнными правками.
- `catalog.js` загружает и отображает список партий. Поисковый запрос и номер страницы хранятся в памяти приложения.
- `editor.js` хранит полную историю, выбранный полуход и сведения о партии. Обработчики DOM передают редактору ввод хода, выбор позиции и изменение полей.
- `board.js` отображает позицию и преобразует клик или перетаскивание в действия на доске.
- `pgn.js` проверяет заголовки и запись ходов, формирует PGN для сохранения и экспорта.
- `api.js` отправляет запросы, разбирает ответы и передаёт ошибки экрану, который выполнял запрос.

## Маршруты приложения

| Маршрут | Назначение |
|---|---|
| Пустой фрагмент URL или `#/` | Страница «Партии» |
| `#/new` | Новая партия или импортированный черновик |
| `#/game/{id}` | Сохранённая партия |
| Другой фрагмент URL | Сообщение о неизвестной странице со ссылкой на страницу «Партии» |

После первого успешного сохранения клиент заменяет `#/new` на `#/game/{id}` в текущей записи истории браузера. Если партия недоступна, можно повторить запрос или вернуться к списку.

При несохранённых правках переход к списку или другой партии, замена черновика и переходы по истории браузера требуют подтверждения. При отмене перехода редактор сохраняет прежнюю партию и адрес страницы. При закрытии или обновлении вкладки приложение запрашивает стандартное предупреждение браузера.

### Размещение в подкаталоге

Базовый путь `/chess-station/` задан в `vite.config.js`. HTML, JavaScript, CSS и SVG загружаются из этого подкаталога. Фрагмент URL остаётся в браузере, поэтому Nginx отдаёт одну страницу, а JavaScript открывает нужный экран.

## Взаимодействие с серверной частью

При загрузке списка клиент получает имена игроков, событие, дату и результат. При открытии отдельной партии сервер возвращает исходный PGN. Для сохранения новой или изменённой партии клиент передаёт полный PGN.

| Метод | Путь | Действие веб-клиента |
|---|---|---|
| `GET` | `/games` | Загрузка списка партий или страницы результатов поиска |
| `POST` | `/games` | Первое сохранение новой или импортированной партии |
| `GET` | `/games/{id}` | Загрузка сохранённой партии вместе с PGN |
| `PUT` | `/games/{id}` | Замена PGN сохранённой партии |
| `DELETE` | `/games/{id}` | Удаление сохранённой партии |

Пути указаны относительно `/chess-station/api/v1`. Веб-интерфейс и API размещены на одном сайте. На сервере запросы передаёт Nginx, при локальной разработке – Vite. Операции с партиями описаны в контракте v1. [Swagger UI](http://201.34.159.85/chess-station/api-docs/)

## API-слой

В v1 API-клиент отвечает за запросы к серверу из списка партий и редактора.

- Построение полного URL операции.
- Передача параметров поиска и пагинации.
- Разбор ответа и передача HTTP-статуса и данных ошибки экрану, который выполнял запрос.

## Состояние редактора

Состояние редактора v1 включает полную историю ходов, позицию просмотра и сведения о партии.

### Полная история и позиция просмотра

История содержит полуходы и позиции после них, полученные из `chess.js`. При переходе назад редактор восстанавливает позицию выбранного полухода и сохраняет продолжение в истории. Повтор записанного хода переводит просмотр на следующий полуход. Новый ход из середины партии заменяет последующие ходы только после подтверждения.

### Результат партии

Если новый ход ставит мат, редактор записывает победу поставившей мат стороны. При пате он записывает `1/2-1/2`. Результат также можно указать вручную.

Если новый ход отбрасывает продолжение с матом или патом, редактор сбросит соответствующий результат на `*` при отсутствии мата или пата в новой позиции. Для загруженной партии это правило действует, если записанный результат соответствует её окончанию. В остальных случаях ручной результат сохраняется, если новый ход не приводит к мату или пату.

Просмотр более ранних позиций не меняет результат. В сформированном PGN тег `Result` совпадает с завершающим маркером.

### Несохранённые изменения

Редактор отслеживает изменения в истории ходов и метаданных. Выделение фигуры, переворот доски и просмотр другой позиции не считаются правками. У пустой новой партии нет несохранённых изменений. Импортированный черновик считается изменённым сразу. После успешного ответа редактор использует полученные от сервера данные как сохранённую версию партии.

## Список партий и поиск

Список загружает по 20 партий на страницу. Поиск по имени белых или чёрных выполняется на сервере.

- Кнопка «Найти» или клавиша Enter запускает поиск с первой страницы.
- При возврате из редактора поисковый запрос и номер страницы восстанавливаются из памяти приложения.
- После сохранения или удаления клиент загружает список заново. Если на странице удалена последняя партия, открывается ближайшая существующая страница. При пустой базе остаётся первая страница.
- Интерфейс различает загрузку списка, пустую базу, отсутствие совпадений и ошибку запроса.

## Управление доской и редактирование партии

При открытии редактора белые находятся снизу. В новой партии показана начальная позиция, в сохранённой или импортированной – позиция после последнего хода.

- Перевернуть доску. Координаты меняют ориентацию вместе с фигурами.
- Сделать ход кликом или перетаскиванием. Редактор отмечает выбранную фигуру, допустимые клетки, последний ход и короля под шахом.
- Выполнить рокировку, взятие на проходе или превращение. При превращении пользователь выбирает фигуру. Отмена выбора или недопустимое перетаскивание сохраняют прежнюю позицию.
- Перейти к нужному полуходу кнопками, выбором хода в панели, стрелками клавиатуры или колесом над доской. Стрелки не перехватываются в полях формы. Колесо над доской переключает полуходы без прокрутки страницы.
- Изменить имена белых и чёрных, событие, дату или результат.
- Удалить сохранённую партию после подтверждения.

## Импорт, сохранение и экспорт PGN

Импорт и экспорт PGN в v1 выполняются средствами браузера.

### Импорт

Редактор v1 рассчитан на одну партию по стандартным правилам шахмат, с обычной начальной расстановкой и одной последовательностью ходов без ответвлений. За один импорт принимается один файл UTF-8. Начальный BOM удаляется, переводы строк LF и CRLF допустимы. Размер PGN ограничен 128 КиБ. Заголовки и поддерживаемый формат записи проверяются до воспроизведения в строгом режиме `chess.js`. Тег `Variant` допускается только со значением `Standard`. Теги `SetUp` и `FEN`, варианты, комментарии и аннотации ходов выходят за пределы формата редактора.

Для импорта следует выгружать одну классическую партию без вариантов, комментариев, оценок и аннотаций времени.

Если файл не проходит проверку, редактор оставляет текущую партию и её правки на экране. Замена партии с несохранёнными изменениями требует подтверждения. Успешный импорт открывает черновик в редакторе.

Если в PGN есть тег `Result` и завершающий маркер, их значения должны совпасть. Если указан только один из них, он определяет результат импортируемой партии. При отсутствии обоих используется `*`. При открытии сохранённой партии редактор также сверяет результат с серверными метаданными. Для партии вне поддерживаемого формата доступны исходный текст, экспорт оригинала и удаление. При редактировании поддерживаемой записи дополнительные заголовки сохраняются. При правке ходов `ECO`, `Opening` и `PlyCount` автоматически не пересчитываются.

### Сохранение и экспорт

Черновик появляется в базе после первого успешного сохранения. При правке сохранённой партии клиент отправляет полный PGN по её идентификатору. Если правок нет, повторный `PUT` не нужен. До ответа сервера приложение блокирует повторное сохранение и действия, которые могут сменить или изменить сохраняемую партию. При ошибке ходы и поля остаются в редакторе, а правки можно экспортировать. Если сервер вернул `404 GAME_NOT_FOUND`, редактор сообщает, что сохранённая партия больше недоступна, и оставляет правки на экране.

При экспорте сохранённой партии без правок редактор выгружает исходный PGN. Для черновика и партии с правками сохранение и экспорт используют один генератор PGN. Он получает полную историю и текущие метаданные, даже если на доске показан промежуточный полуход.

## Обработка ошибок

Веб-интерфейс v1 различает ошибки проверки формы, HTTP-ошибки API и сетевые ошибки.

Ошибки проверки формы отображаются рядом с соответствующими полями.

При известном коде ошибки API интерфейс показывает сообщение сервера и сведения по полям, если они есть. Для неизвестного кода используется общее сообщение о неуспешной операции.

При сетевой ошибке или ответе с ошибкой в другом формате интерфейс сообщит о недоступности сервера и позволит повторить действие.

Сообщения API и содержимое PGN выводятся как текст.

### Работа с `204 No Content`

При успешном удалении сервер возвращает `204 No Content`. Такой ответ не содержит JSON-тела, поэтому API-клиент не вызывает `response.json()` для статуса `204`. При возврате к списку интерфейс загрузит актуальные данные.

## Интерфейс

На широком экране доска расположена в центре, сведения и действия с партией – слева, история и навигация по полуходам – справа. Размер доски зависит от ширины и высоты окна. На узком экране панели размещаются под доской, сначала ходы, затем сведения о партии. Буквенные и числовые координаты вынесены за пределы клеток.

## Переменные окружения

Прокси Vite по умолчанию использует локальный Express на порте `3001`. Если адрес отличается, создайте `.env` на основе `.env.example` и измените `API_PROXY_TARGET`.

```env
API_PROXY_TARGET=http://127.0.0.1:3001
```

Переменная задаёт адрес Express для прокси Vite без пути `/api/v1`. Параметры опубликованного прокси задаются в Nginx.

## Установка

Для разработки и сборки используется Node.js 24.

Установите зависимости:

```bash
npm ci
```

## Запуск веб-интерфейса

Запустите `chess-station-api` с инициализированной базой по инструкции из серверного README. Чтобы заполнить каталог, выполните `npm run seed:demo` в репозитории API при запущенном Express. Затем запустите Vite в репозитории веб-интерфейса.

```bash
npm run dev
```

После запуска Vite покажет локальный адрес приложения. Если порт `5173` свободен, используется адрес:

```text
http://127.0.0.1:5173/chess-station/
```

Проверка frontend-кода через ESLint:

```bash
npm run lint
```

Для файлов в `src/` настроено окружение браузера, для `vite.config.js` – Node.js. Каталог `dist/` исключён из проверки.

## Сборка

Production-сборка:

```bash
npm run build
```

Результат сборки создается в папке `dist`.

### Развёртывание

ChessStation развёрнут по пути `/chess-station/` на сервере, где уже работает Система заметок с тегами ([http://201.34.159.85/notes/](http://201.34.159.85/notes/)), разработанная в рамках курсового проекта прошлого семестра. Чтобы сохранить доступность системы заметок при развёртывании ChessStation, его маршруты заданы в отдельном файле конфигурации Nginx. Nginx обслуживает статическую сборку веб-интерфейса и передаёт запросы к API и документации в Express.

При публикации содержимое `dist/` размещается в `/var/www/chess-station`. JavaScript, стили и SVG загружаются с того же сайта.

## Локальная проверка связи с серверной частью

1. Запустите `chess-station-api` по инструкции из серверного README.
2. Если порт Express отличается от `3001`, укажите адрес Express в `API_PROXY_TARGET`. Затем запустите Vite.
3. Проверьте запрос `GET /chess-station/api/v1/games` на локальном адресе Vite. Прокси передаст его в Express как `GET /api/v1/games`. Ответ `200` содержит список метаданных и общее число партий. Для пустой базы `items` пуст и `total` равен нулю.

3. Сделать новый ход из промежуточной позиции. Проверить подтверждение, отмену замены продолжения и изменение результата.
4. Проверить, что ошибка импорта или сохранения оставляет текущие правки в редакторе.
5. Экспортировать партию из промежуточной позиции и проверить полную историю. Для неизменённой партии сравнить экспорт с исходным PGN.
6. Сохранить новую партию и обновить страницу. Проверить совпадение истории и сведений о партии, затем удалить запись.
7. Проверить размеры и координаты доски, расположение панелей и доступность кнопок на широком и узком экране.

## Преимущества архитектуры v1

- Полная история отделена от позиции просмотра, поэтому сохранение и экспорт включают все ходы.
- Общий обработчик применяет одни правила при клике и перетаскивании.
- Проверка PGN до замены открытой партии сохраняет текущие правки при ошибке импорта.
- Формирование PGN в браузере позволяет экспортировать черновик при недоступности сервера.

## Недостатки первой версии

- При прямой работе с DOM обновление доски, панели ходов и формы нужно явно вызывать при изменении состояния редактора.
- Часть партий, сохранённых через API, нельзя открыть для правки из-за ограничений формата редактора. Для них доступны исходный PGN, экспорт и удаление.
- При одновременной правке последнее успешное сохранение заменяет предыдущую версию партии.

## Изначально заложенные ограничения

- Одна история ходов со стандартной начальной позиции. Новый ход из промежуточной позиции заменяет продолжение после подтверждения. Для хранения вариантов потребуются модель ветвлений, выбор активного варианта и привязка комментариев к ходам.
- Поиск по именам игроков. Поиск по событиям, дебютам и позициям относится к следующим версиям.
- Доступ без учётной записи. Демонстрационный режим использует общий список партий.
- Единая адаптивная вёрстка. Отдельный мобильный режим в v1 не предусмотрен.

## Изначально заложенная расширяемость

- API-клиент отделяет работу с сервером от разметки и управления доской. При сохранении HTTP-контракта интерфейс можно развивать независимо от сервера.
- Модуль PGN получает историю и метаданные партии. Менять отображение ходов и полей формы можно независимо от правил формирования PGN.

## Концепция и перспективы развития

### Другие интерфейсы ChessStation

Браузер – один из способов работы с ChessStation. Тот же API смогут использовать приложение для компьютера и мобильное приложение. В командной строке можно будет искать партии и выгружать PGN. Интерактивный терминальный интерфейс сможет показывать доску и фигуры текстовыми символами и принимать ходы с клавиатуры.

### Расширенный поиск, дебютный справочник и репертуар

Поиск можно будет вести по событию, ходу или позиции. Из результатов поиска по ходам и позициям можно будет перейти к найденному полуходу. Дебютный справочник свяжет название системы с партиями. Дерево продолжений покажет варианты, частоту их применения и результаты. Из выбранной линии можно будет перейти к сыгранным партиям или сохранить её в личном репертуаре за белых или чёрных.

### Варианты, позиции и анализ движком

В редакторе вариантов можно будет сохранять несколько продолжений из одной позиции, переключаться между ними и добавлять к ходам комментарии и пометки. Позицию можно будет загрузить из FEN или задать вручную на доске. Шахматный движок оценит выбранную позицию и предложит сильные продолжения. Пользователь сможет сравнить их со сыгранным ходом и сохранить анализ.

### Серверная проверка легальности ходов

В первой версии легальность ходов проверяет веб-редактор. Когда такая проверка появится и на сервере, редактор продолжит проверять ходы при вводе и сможет показывать причину отказа, полученную от API.

### Подготовка, обучение и публикация

При подготовке к сопернику можно будет отобрать его партии, сравнить выбор дебютов за белых и чёрных и перейти из отчёта к нужной позиции. Партии, позиции и линии репертуара смогут стать материалом для упражнений. Разбор партии можно будет публиковать вместе с вариантами и комментариями.
